One system for every Section 9 output

Documents, decks and dashboards share one base of tokens. Two themes sit on it: Professional, taken from the approved portfolio, and Section 9, the GITS-95 ops room. Same components, same spacing scale, different room.

Theme: Professional, dark mode. Use the button in the header to compare.

Quick start

Three token files and one stylesheet. No build step, no framework, no JavaScript required for the components.

htmlhead
<html data-theme="professional" data-mode="dark">
  <link rel="icon" href="data:image/svg+xml,…">
  <link rel="stylesheet" href="crew/design/tokens/base.css">
  <link rel="stylesheet" href="crew/design/tokens/professional.css">
  <link rel="stylesheet" href="crew/design/components.css">
</html>

For the ops room, swap the theme file and drop the mode:

htmlops-room page
<html data-theme="section9">
  <link rel="stylesheet" href="tokens/base.css">
  <link rel="stylesheet" href="tokens/section9.css">
  <link rel="stylesheet" href="components.css">
</html>

Pages in this folder also load theme.js for the header switch. Consumers do not need it.

Every page carries a favicon so a static server never 404s on /favicon.ico: the mark in favicon.svg, inlined as a data URI so it adds no request. Keep the two in step — tools/check.py fails if the inline copy drifts from the file. A night folder does the same in its dist/index.html.

Two themes, one component sheet. Never mix them inside one surface.

Space, radius, elevation

Spacing

4px grid, --sp-1 (4px) to --sp-24 (96px). Section gaps use 8–12, component padding 4–5, page gutters --gutter.

Radius

Professional: 16px cards, 10px tiles, 6px controls. Section 9 sets every radius to 0 and notches card corners with --notch.

Elevation

Three shadows. Professional reads them as depth; Section 9 turns them into phosphor glow and 1px hairline shadows.

Measure

68ch for prose, 46ch for tight column copy, 76rem page wrap. Long-form slides stay under 40 words per bullet block.

Motion

Motion is 120–560ms on --ease-out. It confirms a state change; it never decorates one. Section 9's scanline is the only ambient animation and it is off under prefers-reduced-motion.

cssthe reduced-motion contract
/* base.css, once */
@media (prefers-reduced-motion: reduce) {
  :root { --dur-1: 1ms; --dur-2: 1ms; --dur-3: 1ms; --dur-4: 1ms; --scan-opacity: 0; }
}

/* a component animates only where motion is welcome */
@media (prefers-reduced-motion: no-preference) {
  html[data-theme="section9"] .shell__scan { animation: shell-scan 14s linear infinite; }
}

Charts

Six categorical series in --chart-1 to --chart-6, fixed order. Series one is the accent; the rest step away in hue and lightness. Grid and axis lines use --chart-grid and --chart-axis.

.chart, .chart__bar, .legend

Charts are hand-built from divs or inline SVG; the palette is the contract, not a library. Give the plot a role="img" and a label that states the finding, and always show the same numbers in a table or a stat beside it.

Accessibility

  • Every text/background pair in both themes clears 4.5:1; the lowest shipped pair is 4.91:1 (Professional faint on surface). Large text and UI edges clear 3:1.
  • Focus is always visible: 2px solid var(--focus) with a 3px offset. Section 9 uses amber, Professional the accent.
  • prefers-reduced-motion kills the scanline, all transitions and the deck transitions; nothing communicates state by motion alone.
  • Do not use colour alone: badges carry a word ("passing", "74%"), calls carry their own icon and title.
  • Targets are at least 44px high (.btn is 2.75rem), including the dashboard rail links, the bottom dock and the skip link; aim for one-handed reach on a phone. The dashboard rail folds at 860px and docks at 480px, and neither scrolls sideways.
  • Text is 16px. Labels — eyebrow, badge, tag, table header, kicker and small copy — are the exception: 12px is the floor. The eyebrow is a label, not decoration, so it stays at 12px (see the README).
  • Use real elements: table with caption and th scope, nav with a label, aria-current for the active page, role="img" plus a sentence for charts.

Using the tokens outside CSS

tokens/tokens.json carries the same values for slides, documents and scripts: base scales under base, per-theme colours under palettes, and the semantic slot list that any renderer must support. CSS remains the source of truth.

For Slides decks, claude-design-system.md is the human- and model-readable brief: tokens, type, colour use and the slide rules, in one file.

The Hermes dashboard theme (hq/ghost.yaml) maps Section 9 onto the dashboard's own palette contract: background #060b09, midground #8bffbe, foreground #e6f2ea, amber focus, zero radius. Keep the two in step when either changes.

Do and don't

✓
Do Use one accent per region; keep body copy at 16px with a 68ch measure; give every table a caption; let Section 9 be dark-only.
×
Don't Hardcode a hex outside the token files, tint body text with the accent, mix themes on one surface, or animate anything that is not a state change.

Checks

tools/check.py parses the three token files, compares every value with tokens.json, and recomputes the contrast pairs declared in tokens/contrast.json. Run it after any token change:

bashno dependencies
python3 crew/design/tools/check.py crew/design
# ok 151 checks: 127 token values in sync, 24 contrast pairs pass AA
#    favicon: 4 page(s) carry favicon.svg inline

Visual checks: the contact sheet, the dashboard and the deck template are all served from this folder and screenshotted at 1440px and 390px in both themes, then run through Impeccable (detect).
